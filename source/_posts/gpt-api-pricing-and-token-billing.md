## 一、GPT API 是怎么收费的？

GPT API 通常采用**按量计费**模式，也就是“用多少，付多少”。

计费的核心单位是 **Token**。

一次 GPT调用 的费用，主要由以下因素决定：

- 使用的模型
- 输入的 Token 数量
- 输出的 Token 数量
- 部分模型的推理 Token
- 是否使用图片等多模态内容
- 平台自身的计费规则

简单理解：

```text
单次调用费用 = 输入 Token 费用 + 输出 Token 费用
```

所以，**同样一个问题，换一个模型、换一种问法、让模型多写或少写，价格都可能不同。**

---

## 二、Token 是什么？

Token 可以理解为大模型处理文本的**最小单位**。

模型不是按“字”或“词”来读取内容的，而是先把文本切分成一个个 Token，再进行计算。

### 1. 英文 Token

英文中，一个常见单词可能是 1 个 Token，较长或较少见的单词可能会被拆成多个 Token。

例如：

```text
"Hello world" 大约是 2 个 Token
```

### 2. 中文 Token

中文的切分方式和英文不同。不同模型使用的分词器不同，中文字符与 Token 的比例也会有差异。

一般可以粗略估算为：

```text
1 个汉字 ≈ 1 ~ 2 个 Token
```

> 注意：这只是经验估算值，实际消耗请以接口返回的 `usage` 字段或平台扣费记录为准。

### 3. 哪些内容会消耗 Token？

很多人以为只有“用户的问题”才算 Token，其实以下内容**全部都会计入**：

- System Prompt（系统提示词）
- 用户本次输入
- 多轮对话的历史消息
- 知识库检索后拼接进来的文档片段
- 模型生成的回答
- 部分推理模型的思考过程

这也是很多项目成本失控的根本原因。

## 三、为什么输入和输出价格不一样？

在查看 GPT API价格 时，你会发现大多数模型都会分开标注：

- **输入价格（Input / Prompt）**
- **输出价格（Output / Completion）**

并且通常**输出价格明显高于输入价格**。

原因在于：

- 输入内容可以并行处理，计算效率较高
- 输出内容需要逐个 Token 生成，计算成本更高

这意味着：

> 让模型“多读”通常比让模型“多写”更便宜。

在设计 AI 功能时，这一点非常重要。比如：

- 摘要任务：输入长、输出短，成本相对可控
- 长文写作：输入短、输出长，成本主要在输出
- 多轮聊天：输入会随轮数不断增长，需要特别注意

## 四、不同类型模型的价格差异

不同模型的价格差距可能非常大，有时相差几倍甚至几十倍。

### 1. 轻量模型

例如 `gpt-4o-mini` 这类轻量模型：

- 单价低
- 速度快
- 适合高频调用

适合：普通聊天、文本分类、翻译、改写、摘要、标题生成。

### 2. 旗舰模型

例如 `gpt-4o` 等能力更强的模型：

- 单价较高
- 输出质量更好
- 适合复杂任务

适合：高质量写作、复杂问答、代码生成、长文档分析。

### 3. 推理模型

部分推理类模型在回答前会进行内部“思考”。

需要注意：

- 推理过程可能产生额外的 Token
- 这部分 Token 通常按输出价格计费
- 即使最终回答很短，实际消耗也可能较多

所以推理模型更适合真正需要深度推理的场景，不建议用来做简单闲聊。

### 4. Embedding 向量模型

Embedding 模型用于知识库、语义搜索，通常：

- 只计算输入 Token
- 单价通常较低
- 适合批量处理文档

### 5. 图像与多模态模型

图片相关模型的计费方式可能比较特殊，例如：

- 按图片张数计费
- 按图片分辨率或尺寸计费
- 图片输入折算成 Token 计费

具体规则需要查看平台价格说明。

## 五、GPT中转站是怎么计费的？

如果你使用的是 **GPT API中转站**，计费方式通常和官方 API 的逻辑类似，也是基于 Token 用量，但展示方式可能不同。

### 1. 按 Token 直接计价

平台直接标注每个模型的输入、输出单价，例如：

```text
输入：X 元 / 百万 Token
输出：Y 元 / 百万 Token
```

这种方式最直观，适合直接估算成本。

### 2. 按“额度 + 倍率”计费

不少中转平台会采用“额度 + 倍率”的展示方式，常见概念包括：

- **模型倍率**：不同模型的基础价格系数
- **补全倍率**：输出 Token 相对于输入 Token 的价格系数
- **分组倍率**：不同用户分组或渠道的价格系数

大致计算逻辑类似：

```text
消耗额度 = (输入 Token + 输出 Token × 补全倍率) × 模型倍率 × 分组倍率
```

> 不同平台的具体公式和换算规则可能不同，请以平台的价格页面说明为准。

### 3. 充值与额度换算

部分平台会将充值金额换算成平台额度，然后按调用消耗扣除。

充值前建议确认：

- 充值金额和额度如何换算
- 不同模型的实际单价
- 额度是否有有效期
- 是否支持查看每次调用的扣费明细
- 是否有最低充值金额

## 六、GPT API 成本估算公式

你可以用下面这个公式估算 GPT调用 的成本：

```text
单次费用 = 输入Token数 ÷ 1,000,000 × 输入单价
         + 输出Token数 ÷ 1,000,000 × 输出单价

月度费用 = 单次平均费用 × 每日调用次数 × 30
```

### 估算示例

> 以下单价仅为**示例假设**，用于演示计算方法，并非任何模型的真实价格。

假设某模型：

- 输入单价：1 元 / 百万 Token
- 输出单价：4 元 / 百万 Token

你的 AI 客服系统：

- 每次请求平均输入 1,500 Token（含系统提示词和历史消息）
- 每次请求平均输出 500 Token
- 每天调用 10,000 次

计算：

```text
每日输入 Token = 1,500 × 10,000 = 15,000,000
每日输出 Token = 500 × 10,000 = 5,000,000

每日费用 = 15 × 1 + 5 × 4 = 35 元
每月费用 ≈ 35 × 30 = 1,050 元
```

把公式里的单价换成你所用平台的实际价格，就能得到比较接近的预算。

## 七、多轮对话的成本为什么越来越高？

这是很多聊天类产品最容易忽视的问题。

GPT API 本身没有记忆，要实现多轮对话，每次请求都需要把历史消息一起发送。

假设：

- 系统提示词：200 Token
- 每轮用户提问：100 Token
- 每轮模型回答：300 Token

那么每一轮的**输入 Token** 大致是：

| 对话轮数 | 本轮输入 Token（约） |
| --- | --- |
| 第 1 轮 | 200 + 100 = 300 |
| 第 2 轮 | 300 + 300 + 100 = 700 |
| 第 5 轮 | 约 1,900 |
| 第 10 轮 | 约 3,900 |
| 第 20 轮 | 约 7,900 |

可以看到，对话越长，单次请求的输入成本越高。

如果你的产品不做历史裁剪，聊到后期，**一次请求的成本可能是第一轮的几十倍**。

## 八、如何查看每次调用消耗了多少 Token？

### 1. 读取接口返回的 usage 字段

兼容 OpenAI 格式的接口，普通请求通常会在返回结果中包含 `usage` 字段：

```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "这是模型的回答。"
      }
    }
  ],
  "usage": {
    "prompt_tokens": 56,
    "completion_tokens": 120,
    "total_tokens": 176
  }
}
```

其中：

- `prompt_tokens`：输入 Token
- `completion_tokens`：输出 Token
- `total_tokens`：总 Token

### 2. Python 统计 Token 和费用示例

```python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://jeniya.cn/v1"
)

# 示例单价（元 / 百万 Token），请替换为平台实际价格
PRICE_TABLE = {
    "gpt-4o-mini": {"input": 1.0, "output": 4.0},
    "gpt-4o": {"input": 15.0, "output": 60.0},
}

def chat_and_count(model, messages):
    response = client.chat.completions.create(
        model=model,
        messages=messages,
        max_tokens=800
    )

    usage = response.usage
    price = PRICE_TABLE.get(model, {"input": 0, "output": 0})

    cost = (
        usage.prompt_tokens / 1_000_000 * price["input"]
        + usage.completion_tokens / 1_000_000 * price["output"]
    )

    print(f"模型: {model}")
    print(f"输入 Token: {usage.prompt_tokens}")
    print(f"输出 Token: {usage.completion_tokens}")
    print(f"预估费用: {cost:.6f} 元")

    return response.choices[0].message.content

answer = chat_and_count(
    "gpt-4o-mini",
    [{"role": "user", "content": "请用三句话介绍 GPT API 的计费方式。"}]
)

print(answer)
```

### 3. 流式输出时统计 Token

开启 `stream: true` 后，默认可能不会返回 `usage`。

部分兼容 OpenAI 格式的接口支持通过 `stream_options` 在最后一个数据块中返回用量：

```python
stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "介绍一下 Token"}],
    stream=True,
    stream_options={"include_usage": True}
)

for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
    if chunk.usage:
        print("\n用量:", chunk.usage)
```

> 是否支持 `stream_options` 需要以平台文档为准。

### 4. 请求前预估 Token

如果想在发送请求前估算 Token 数量，可以使用 `tiktoken` 库：

```bash
pip install tiktoken
```

```python
import tiktoken

encoding = tiktoken.get_encoding("o200k_base")

text = "GPT API 是按照 Token 数量进行计费的。"
tokens = encoding.encode(text)

print("Token 数量：", len(tokens))
```

> 本地计算结果仅用于预估，消息格式本身也会占用少量 Token，实际扣费以平台记录为准。

## 九、降低 GPT API 成本的 8 个实用技巧

### 1. 按任务分配模型

不要所有请求都用最贵的模型。

| 任务类型 | 建议模型类型 |
| --- | --- |
| 闲聊、分类、改写 | 轻量模型 |
| 普通问答、摘要 | 轻量或中等模型 |
| 高质量写作、复杂分析 | 旗舰模型 |
| 深度推理、数学、复杂代码 | 推理模型 |
| 知识库检索 | Embedding 模型 |

### 2. 精简系统提示词

系统提示词每次请求都会被计费。

一段 1,000 Token 的系统提示词，调用 10 万次就是 1 亿 Token 的输入。能用 200 Token 说清楚的规则，就不要写成 1,000 Token。

### 3. 裁剪多轮对话历史

- 只保留最近 5~10 轮
- 对早期对话做摘要
- 删除与当前问题无关的内容

### 4. 设置 max_tokens

```json
{
  "max_tokens": 500
}
```

避免模型输出过长内容，尤其适合标题生成、关键词提取、分类等短输出任务。

### 5. 在提示词中约束输出长度

例如：

```text
请用不超过 100 字回答。
只输出 JSON，不要额外解释。
```

输出越短，费用越低。

### 6. 知识库只传相关片段

做 RAG 知识库时，不要把整篇文档塞进请求，只传检索出的最相关的几个片段。

### 7. 对高频重复问题做缓存

例如：

- 常见问题回答
- 固定产品介绍
- 标准化翻译内容

相同问题直接返回缓存结果，不再重复调用 API。

### 8. 给每个 API Key 设置额度

很多 GPT API中转站支持为不同 Key 设置额度上限。

建议：

- 测试环境和生产环境使用不同 Key
- 每个项目使用独立 Key
- 为每个 Key 设置额度上限
- 定期查看调用日志

这样即使 Key 泄露或程序出现死循环，损失也能被控制在可接受范围内。

## 十、不同业务场景的成本特点

### AI 聊天机器人

- 成本主要来自多轮历史消息
- 重点优化：历史裁剪、摘要、轻量模型

### AI 写作工具

- 成本主要来自输出 Token
- 重点优化：控制文章长度、分段生成、按需选择模型

### 智能客服

- 调用量大、问题重复率高
- 重点优化：缓存常见问题、使用轻量模型、精简系统提示词

### 知识库问答

- 成本来自 Embedding + 检索片段 + 回答生成
- 重点优化：控制检索片段数量和长度

### AI 编程助手

- 代码上下文长，输入 Token 较多
- 重点优化：只传相关代码文件，避免一次性传入整个项目

## 十一、选择 GPT中转站时，价格要怎么看？

不要只看“谁的单价最低”，还要综合考虑：

1. **价格是否透明**：每个模型的输入、输出价格是否清晰标注
2. **扣费是否可查**：是否能看到每次调用的 Token 和扣费明细
3. **模型是否真实**：低价是否以牺牲模型质量为代价
4. **稳定性如何**：频繁失败和重试也会增加隐性成本
5. **是否支持额度控制**：能否给 Key 设置上限
6. **是否有隐藏费用**：充值门槛、额度有效期等规则是否明确

一个价格稍高但稳定、透明的平台，往往比低价但频繁报错的平台**综合成本更低**。

## 十二、常见问题 FAQ

### GPT API 是按次收费还是按 Token 收费？

通常按 Token 收费，而不是按请求次数收费。同样是一次请求，内容越长费用越高。

---

### 1 个汉字等于多少 Token？

不同模型的分词方式不同，一般可以粗略估算为 1 个汉字约 1~2 个 Token，实际以接口返回的 `usage` 为准。

---

### 为什么我只问了一句话，消耗的 Token 却很多？

可能是因为请求中还包含了系统提示词、多轮历史消息、知识库片段，或者使用了会产生推理 Token 的模型。

---

### 调用失败会扣费吗？

不同平台规则不同。一般来说，请求未被模型成功处理时通常不会扣费，但请以平台计费说明和扣费记录为准。

---

### GPT中转站的价格比官方便宜吗？

不一定。不同平台的定价策略、模型来源和服务内容不同，建议结合价格、稳定性和服务质量综合比较。

---

### 测试阶段如何控制费用？

建议使用轻量模型测试、设置 `max_tokens`、给测试 Key 设置额度上限，并在代码中记录每次调用的 Token 消耗。

---

### 怎么知道每个月大概要花多少钱？

先在测试阶段统计单次请求的平均输入和输出 Token，再乘以模型单价和预计调用量，就可以得到比较接近的月度预算。
